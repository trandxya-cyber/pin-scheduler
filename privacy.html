v1lads Pin Scheduler · Updated October 21, 2026

Project status. v1lads Pin Scheduler is a private Pinterest publishing automation project under development. This policy describes the proposed data handling of the application. It must be updated to match the actual deployed implementation before public use.

2. Information required by the application

Once implemented and authorized, the workflow is designed to access only the information necessary for the selected publication task, such as Pinterest account identifiers, destination board identifiers, user-selected images, Pin titles and descriptions, destination links, planned publication times, and returned Pin identifiers or error messages.

Where an account is connected using Pinterest OAuth, the workflow may also handle access and refresh tokens to maintain the authorized connection. It is not designed to request Pinterest account passwords.

3. Why the information is used

These data will be used to identify the correct authorized account and board, publish individual Pins selected in advance by the operator, maintain a publishing queue, and record errors or successful publication results. The integration is not designed to sell account or content data.

4. Storage and third-party services

The planned workflow uses local files for source images and Google Sheets to manage the publishing queue. Authorized Pin content is transmitted to Pinterest in order to publish it. Google processes data held in the connected spreadsheet. The configured automation provider or locally hosted automation service, if used, may also process operational data and credentials as necessary for the integration.

The informational website is hosted on GitHub Pages. GitHub may process technical information about site visitors in accordance with its own privacy statement. This website has no contact form or application login feature.

5. Access controls and retention

Access to connected Pinterest accounts should be granted only by the account owner through Pinterest's authorization flow. Credentials and tokens must not be stored in this public GitHub Pages repository. Publishing records and account credentials should be kept only as long as operationally required, with access limited to authorized operators.
